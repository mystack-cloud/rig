# CLI-Only Solution with Hetzner S3-Compatible Storage

## Overview

This document describes the implementation of a CLI-only solution focused on Hetzner S3-compatible object storage using Hetzner Cloud Token authentication. The solution provides a command-line interface for managing storage operations without requiring explicit S3 credentials.

## Implementation Details

### 1. Core Components

#### Storage Manager Module
- **File**: `src/cli/storage.py`
- **Purpose**: Manages all S3-compatible storage operations
- **Features**:
  - Bucket creation/deletion
  - File upload/download functionality
  - Object listing and deletion
  - Configuration via environment variables
  - Default Hetzner endpoint (`fsn1`)

#### Main CLI Entry Point
- **File**: `src/cli/main.py`
- **Purpose**: Command-line interface router
- **Commands**:
  - `storage create-bucket`: Create a new storage bucket
  - `storage list-buckets`: List all storage buckets
  - `storage upload`: Upload a file to storage
  - `storage download`: Download a file from storage
  - `storage list-objects`: List objects in a bucket
  - `storage delete-object`: Delete an object from storage
  - `storage delete-bucket`: Delete a storage bucket

#### Configuration Manager
- **File**: `src/cli/config.py`
- **Purpose**: Manages CLI configuration
- **Features**:
  - Loads configuration from file or defaults
  - Supports environment variable overrides
  - Manages configuration persistence

### 2. Storage Capabilities

The solution provides comprehensive storage management for Hetzner S3-compatible storage:

1. **Bucket Management**
   - Create buckets
   - List buckets
   - Delete buckets

2. **Object Management**
   - Upload files with custom object names
   - Download files
   - List objects in buckets
   - Delete individual objects

3. **Authentication**
   - Uses Hetzner Cloud Token for authentication
   - Default endpoint: `https://fsn1.yourdomain.com`
   - Temporary S3 credentials generated by Hetzner

### 3. Credential Management

#### Hetzner Cloud Token Authentication
- **Primary Authentication**: Uses Hetzner Cloud API token for authentication
- **Token Requirement**: Required for all operations
- **Security**: Tokens are never stored permanently, only used for authentication

#### S3 Credential Handling
- **Generation Process**: Hetzner generates temporary S3 credentials on demand
- **Exposure**: S3 credentials are displayed only once during generation
- **Security**: Generated credentials are handled by Hetzner's secure infrastructure
- **Replacement**: When credentials expire, new ones are generated automatically

### 4. Configuration

#### Environment Variables
```bash
export HZ_TOKEN="your-hetzner-cloud-token"
export S3_ENDPOINT_URL="https://fsn1.yourdomain.com"  # Optional override
```

#### Configuration File (`config.yaml`)
```yaml
hz_token: "your-hetzner-cloud-token"
s3_endpoint_url: "https://fsn1.yourdomain.com"
```

### 5. Usage Examples

#### List Buckets
```bash
python3 src/cli/main.py storage list-buckets
```

#### Create Bucket
```bash
python3 src/cli/main.py storage create-bucket --name my-bucket
```

#### Upload File
```bash
python3 src/cli/main.py storage upload \
  --bucket my-bucket \
  --file ./local-file.txt \
  --object-name remote-file.txt
```

#### Download File
```bash
python3 src/cli/main.py storage download \
  --bucket my-bucket \
  --object remote-file.txt \
  --file ./downloaded-file.txt
```

#### List Objects
```bash
python3 src/cli/main.py storage list-objects \
  --bucket my-bucket \
  --prefix "subdirectory/"
```

### 6. Benefits of This Approach

1. **Secure Authentication**: Uses Hetzner Cloud Token instead of static credentials
2. **Automatic Credential Management**: Hetzner generates temporary S3 credentials
3. **Standard Endpoint**: Defaults to `fsn1` region for Hetzner compatibility
4. **Minimal Dependencies**: Lightweight implementation focused on storage operations
5. **S3 Compatibility**: Works with Hetzner and other S3-compatible services
6. **Credential Security**: S3 credentials shown only once, never permanently stored

### 7. Integration with Existing Project

The solution maintains compatibility with the existing project structure:
- Uses the same package structure (`src/cli/`)
- Maintains existing configuration system
- Integrates seamlessly with existing dependencies
- Follows the same naming conventions

### 8. Security Features

1. **Token-Based Authentication**: Uses Hetzner Cloud tokens instead of permanent credentials
2. **Temporary Credentials**: S3 credentials are generated temporarily by Hetzner
3. **Secure Environment Variables**: Stores tokens in environment variables
4. **HTTPS Only**: All operations use secure connections
5. **Credential Masking**: Tokens displayed securely with masking
6. **Auto-Renewal**: Automatic credential renewal when needed
